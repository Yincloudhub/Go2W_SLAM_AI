## 2. 每次测试的固定准备

1. 机器人在视线内，急停可立即操作，速度上限保持 `0.1 m/s`。
2. 确认 Git 工作区、地图、registry 和标定文件版本。
3. 地面标出机器人中心和朝向，照片中放置测试编号。
4. 物理距离从机器人最外缘测量，不从雷达中心测量。
5. 每次改变障碍、姿态或位置后停稳 5 秒再采集。
6. 不允许手工把 `calibrated`、`live_verified` 或锚点状态改成通过。

只读基线：

```bash
cd /home/unitree/Go2W_SLAM_AI
bash scripts/go2w_accept.sh status
bash scripts/go2w_accept.sh snapshot baseline_01
```

带连续定位样本：

```bash
bash scripts/go2w_accept.sh snapshot relocation_origin_01 mapping_origin
```

## 3. 测试矩阵

| 阶段 | 测试 | 最小次数 | 通过标准 |
|---|---|---:|---|
| P0 | 冷启动进程与只读状态 | 3 | 驱动、SLAM、摘要均可解释；无运动命令 |
| P1 | 建图原点重定位 | 5 | 5/5 成功；每次连续 5 帧有效；地图身份一致 |
| P1 | 错误锚点、缺少确认 | 各 1 | 必须拒绝；底盘不运动 |
| P2 | XT16 空场与前后左右障碍 | 5 场 | 方向无颠倒，输出与实测误差可解释 |
| P2 | 四向近障阻断 | 每向 3 | 阈值内 100% 阻断，无漏检 |
| P3 | 三个拓扑点重复到位 | 每点 3 | 位置/朝向离散度可统计，标签状态正确 |
| P4 | 短直行、转弯、返回 | 每路线 3 | 到点自动暂停，无碰撞，无人工接管 |
| P4 | 定位丢失、传感器过期 | 各 3 | 拒绝启动或在 2 秒租约内暂停 |
| P5 | LLM 已知、改写、歧义、无效目标 | 至少 10 | 已知目标正确；歧义和无效目标不执行 |

用于论文或正式材料时，重定位和每条导航路线建议扩展到至少 10 次。

## 4. XT16 人工标定

按空场、前、左、右、后五个静态场景进行。每个障碍优先放在
`0.6-1.5 m` 范围，避开玻璃和镜面；保留现场照片。

每个场景记录：

- 机器人外缘到障碍的卷尺距离；
- XT16 aggregate、body、low-hazard 四向距离；
- 点数、置信度、pending/stale 原因；
- D435 前视中心距离，仅作前方交叉验证；
- 绝对误差和是否触发安全阻断。

至少三组有效实测场景、方向正确且阻断无漏检后，才允许生成非空
`calibration_id` 并把标定记录改为 `verified`。标定状态变更后必须重新
构建、重启侧车并做短距离监督测试。

## 5. 重定位人工校准

`mapping_origin` 与其他重定位点不是同一概念：

- `mapping_origin` 永远只有一个，表示建图坐标原点。
- 同一 PCD 可以有多个重定位锚点，用于机器人在不同已知物理位置启动。
- 导航拓扑点不能直接充当重定位锚点。

当前只允许正式使用 `mapping_origin`。测试时：

1. 对齐地面中心和朝向标记，站立停稳。
2. 启动 SLAM 后只执行一次显式重定位。
3. 保存请求结果、ICP、首帧时间和连续 5 帧位姿。
4. 失败后先检查厘米级平移、约 5 度朝向、玻璃/对称环境和地图身份；
   不连续盲重试。
5. 其他候选锚点在安全 candidate-probe 工具完成前不得提升为 active。

## 6. 拓扑点和导航验收

- 拓扑点先地面标记，再从不同方向进入三次。
- 每次记录最终位置、yaw、距目标误差、最小四向净空、暂停原因。
- `needs_calibration` 或 `needs_standing_verification` 点不得用于真实导航。
- 旧的 `expected_distance_m` 只视为历史占位值。最终值应来自稳定导航
  轨迹长度或重新实测，且不得小于节点间直线距离。
- 首次真实运动只选空旷区 `0.2-0.5 m` 的短目标，确认 XT16 已 verified，
  人员全程跟随并持有急停。

## 7. LLM 测试

LLM 只负责语义和任务编排，不负责放宽安全条件。测试集合至少包含：

- 已知目标的标准说法和多种同义改写；
- 两个目标混在一句话中的顺序任务；
- 未知目标、同名目标、缺少目标；
- 未定位、XT16 过期、目标未验证时的命令；
- “前进十米拍照”等无 SLAM 任务的规划请求。

记录原始指令、期望意图、解析结果、模型耗时、是否修复模型输出、最终
动作和阻断原因。未知或歧义命令必须要求确认，不得猜测执行。

## 8. 材料需要的图表

- 系统闭环流程图：LLM 语义层、确定性状态机、C++ 安全边界、传感器。
- 冷启动重定位成功率、ICP 分布、首帧定位耗时。
- XT16 四向实测值与输出值散点图、绝对误差统计。
- 导航路径、终点误差、最小净空、暂停原因统计。
- LLM 意图准确率、端到端延迟、拒绝/澄清案例。
- 失败案例表：环境、版本、错误码、是否运动、恢复动作。

每条材料数据必须能追溯到 artifact，并包含：

`run_id、时间、git_commit、git_dirty、PCD_SHA256、registry_SHA256、`
`calibration_id、场景、操作员、原始结果和最终判定`。
