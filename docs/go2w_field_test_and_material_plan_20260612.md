## 2. 每次测试的固定准备

1. 机器人在视线内，急停可立即操作，速度上限保持 `0.1 m/s`。
2. 确认 Git 工作区、地图、registry 和标定文件版本。
3. 地面标出机器人中心和朝向，照片中放置测试编号。
4. 物理距离从机器人最外缘测量，不从雷达中心测量。
5. 每次改变障碍、姿态或位置后停稳 5 秒再采集。
6. 不允许手工把 `calibrated`、`live_verified` 或锚点状态改成通过。

```bash
cd /home/unitree/Go2W_SLAM_AI

```

## 4. XT16 正式 measured ledger（非当前重复任务）

本节保留的是将标定记录从 `pending_field_measurement` 提升到 `verified` 时的
严格归档格式，不是下一 Session 必须重新执行的现场任务。已有工程证据包括
2026-06-06 四方向轴向场景、2026-06-13 当前算法走廊基线和 2026-06-14
右侧箱体/开放成对差分。仅在决定签发真实运动，且现有证据无法补齐卷尺真值、
artifact 格式或当前参数一致性时，才补采缺项。

当前 footprint 按 XT16 居中安装采用四向对称待测初值：前、后、左、右均
`0.30 m`。该值不证明机器狗完整运动外廓一定落在 `0.60 x 0.60 m` 内，
不能作为现场标定已经完成或允许真实导航的证据。
另有 `0.05 m` 的机身高度边界自体回波过滤容差，但输出净空仍以名义外廓为零点；
低矮风险不使用额外容差，机身外线缆点仍保留。该值由
2026-06-13 走廊静止基线确定：5 cm 刚好去除后部对称自回波，6-8 cm 不再删除
额外点。

每个场景记录：

- 机器人外缘到障碍的卷尺距离；
- XT16 aggregate、body、low-hazard 四向距离；
- 点数、置信度、pending/stale 原因；
- D435 前视中心距离，仅作前方交叉验证；
- 绝对误差和是否触发安全阻断。

五个场景全部有效、方向正确且阻断无漏检后，才允许生成非空
`calibration_id` 并把标定记录改为 `verified`。标定状态变更后必须重新
构建、重启侧车并做短距离监督测试。

方向场景使用统一只读命令，单位为米：

```bash
bash scripts/go2w_accept.sh xt16-baseline OPERATOR FRONT_M LEFT_M RIGHT_M REAR_M
bash scripts/go2w_accept.sh xt16-scene front OPERATOR 0.80
bash scripts/go2w_accept.sh xt16-scene left OPERATOR 0.80
bash scripts/go2w_accept.sh xt16-scene right OPERATOR 0.80
bash scripts/go2w_accept.sh xt16-scene rear OPERATOR 0.80
```

每次自动采集 25 个不同时间戳并计算中位数、P5/P95、绝对误差、
点云源延迟和处理耗时。`baseline` 必须通过
`capture_xt16_calibration_scene.py` 同时提供四向卷尺实测值。

五个场景全部通过后，用 `finalize_xt16_calibration.py` 汇总。工具会核验
场景集合、artifact 哈希、传感器序列号、参数、Git 提交和工作树状态；
默认只生成候选记录，只有显式传入 `--apply` 才改写运行标定记录。

不得把本节再次路由为“先重复五场”。前视 D435 只能验证前方，不能替代 XT16
的物理左、右、后净空；如果未来需要补齐正式 ledger，应先审计现有 artifact，
列出确实缺失的测量字段，再进行最小补采。

## 5. 重定位人工校准

`mapping_origin` 与其他重定位点不是同一概念：

- `mapping_origin` 永远只有一个，表示建图坐标原点。
- 同一 PCD 可以有多个重定位锚点，用于机器人在不同已知物理位置启动。
- 导航拓扑点不能直接充当重定位锚点。

当前只允许正式使用 `mapping_origin`。测试时：

1. 对齐地面中心和朝向标记，站立停稳。
2. 启动 SLAM 后只执行一次显式重定位。
3. 保存请求结果、ICP、首帧时间和连续 5 帧位姿。
4. 失败后先检查厘米级平移、约 5 度朝向、玻璃/对称环境和地图身份；
   不连续盲重试。
5. 其他候选锚点在安全 candidate-probe 工具完成前不得提升为 active。

## 6. 拓扑点和导航验收

- 拓扑点先地面标记，再从不同方向进入三次。
- 每次记录最终位置、yaw、距目标误差、最小四向净空、暂停原因。
- `needs_calibration` 或 `needs_standing_verification` 点不得用于真实导航。
- 旧的 `expected_distance_m` 只视为历史占位值。最终值应来自稳定导航
  轨迹长度或重新实测，且不得小于节点间直线距离。
- 首次真实运动只选空旷区 `0.2-0.5 m` 的短目标，确认 XT16 已 verified，
  人员全程跟随并持有急停。

## 7. LLM 测试

LLM 只负责语义和任务编排，不负责放宽安全条件。测试集合至少包含：

- 已知目标的标准说法和多种同义改写；
- 两个目标混在一句话中的顺序任务；
- 未知目标、同名目标、缺少目标；
- 未定位、XT16 过期、目标未验证时的命令；
- “前进十米拍照”等无 SLAM 任务的规划请求。

记录原始指令、期望意图、解析结果、模型耗时、是否修复模型输出、最终
动作和阻断原因。未知或歧义命令必须要求确认，不得猜测执行。

当前代码还额外执行以下确定性约束：

- 未定位或 SLAM 异常时，所有 prompt 模式统一转为 `safe_hold`。
- `mapless_scout`、相对运动和原始底盘控制未接线时不得真实执行。
- 只有含“然后、再去、依次、then、and then”等明确顺序证据时，多个目标
  才能构造串行队列；共享别名必须澄清。
- 缺少 `live_verified` 或带 `needs_calibration` 的目标在 planner 层提前阻断，
  gateway 授权器继续保留最终硬门禁。
