## 1. coarse_map 路径校验的教训

### 问题
`check_path()` 使用直线 PCD 密度采样检测穿墙。在室内走廊环境中，两个节点之间直线路径穿过墙壁是正常的——Unitree 规划器会沿走廊绕行。但直线检测把这种场景标记为 blocked，导致所有导航被拦截。

### 修复
将 coarse_map 验证从**强制拦截**改为**建议日志**。Unitree 规划器拥有完整的 PCD 占据栅格，能找到走廊路径。直线采样只适合空旷环境。

### 保留价值
coarse_map 仍然作为 LLM 上下文的一部分——让 LLM 看到墙壁布局有助于理解环境。但不再作为导航门禁。

| 版本 | 行为 |
|------|------|
| `73277fe` | coarse_map 仅 LLM 提示 |
| `2edce2d` | 强制拦截，失败→human_confirm |
| `e385c87` | 建议日志，不拦截导航 |

## 2. 拓扑点语义标签问题

### 问题
`needs_calibration` 标签在 `BLOCKING_NAVIGATION_TAGS` 中，导致 `nie_guoli_office_front` 无法作为导航目标。用户在现场确认位置后，需要去掉此标签才能使用该点。

### 修复
1. 通过 `PersistentGatewaySession.command()` 获取当前 SLAM pose
2. 更新注册表中的坐标和标签
3. 关键：`client_path` 不是 `gateway_client`，方法是 `command()` 不是 `get_world_state()`
