3. 就绪状态不能压成一个布尔值

services_ready

驱动、SLAM 启动脚本和 gateway 查询路径可工作。

relocalization_ready

允许人工确认的重定位；不要求四周都安全，因为不驱动底盘。

execution_arming_ready

定位姿态新鲜有效，可以开启执行模式，但尚不代表可以导航。

perception_ready

XT16 摘要新鲜、正式标定且结构完整。

navigation_ready

SLAM、定位、感知、网关和当前障碍判断全部允许移动。

llm_ready

本地或 HTTP LLM 可用。该状态只影响智能交互，不授予运动权限。

4. 安全闭环

已注册目标拒绝未知、禁用或未验证拓扑点
SLAM 定位pose 字段、四元数、源时间戳有效
XT16 主安全源未标定或陈旧即导航阻断
保守融合双传感器新鲜时按方向取更近障碍
执行凭据仅认可带 runtime watchdog 的入口
连续监控运行时重复读取定位与安全状态
暂停闭环到达、超时或异常都请求暂停
场景规则结果
启动后尚未重定位服务可用，但定位为 not_started禁止导航，允许确认重定位
XT16 未标定或陈旧D435 不得覆盖主安全源的失效状态导航 fail-closed
XT16 与 D435 都新鲜前、左、右方向取更近 clearance，并继承对应置信度按最保守障碍判断
LLM 直接给坐标或 API ID只接受 registry 中的任务级目标拒绝
运行时定位丢失或 gateway 连续错误watchdog 触发暂停并终止队列停止后续动作
到达目标但暂停未被接受不能把“到达”单独视为队列成功任务失败，等待人工检查
重定位与导航是两种不同权限。重定位只恢复 SLAM 坐标，不要求“周围全部安全”；真正导航仍必须经过完整感知和运行期安全闭环。

6. LLM 应发挥的作用

适合交给 LLM

  • 理解自然语言和省略表达
  • 在已注册节点中消歧
  • 生成受 schema 限制的任务序列
  • 解释失败原因并请求人工确认

必须由确定性代码负责

  • 地图和目标是否合法
  • 定位、感知和安全是否新鲜
  • 速度、模式和动作白名单
  • 暂停、超时和故障处置

LLM 明确不能做

  • 直接调用 Unitree API ID
  • 绕过未标定 XT16
  • 把猜测坐标当作真实拓扑点
  • 单独决定开启真实执行

实时性策略

  • 已知目标优先规则和别名匹配
  • 模糊意图才调用本地 LLM
  • LLM 输出小型结构化 JSON
  • 安全门不等待 LLM 推理

7. 人工监督验收顺序

阶段动作通过标准
A. 只读启动启动 XT16、SLAM、gateway，只查询状态motion_commands_sent=false，服务在线
B. 锚点重定位人工确认真实物理锚点后执行 relocate连续 pose 新鲜、坐标与锚点一致、无 ICP 错误
C. 静止安全验证放置和移除前后左右障碍clearance、方向和 stale 状态符合实物
D. 低速单点导航0.1 m/s，短距离，人员持急停运行期 watchdog 生效，到达后暂停被接受
E. 故障注入依次停止点云、geometry、SLAM 和 gateway每项都在约定时间和距离内 fail-closed
F. 标定放行完成全部监督测试后更新标定状态才能设置 GO2W_XT16_GEOMETRY_CALIBRATED=1
