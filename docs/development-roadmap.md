# 推荐开发路线

## 核心原则

把 GO2W 官方 SLAM / Navigation 当成底层能力提供者，而不是第一阶段的主攻对象。

你真正要做的系统创新层是：

- 结构化语义
- 高层任务理解
- 安全监督
- 弱带宽远程交互

## Phase 0：资产恢复与接口对齐

目标：

- 把备份里还能恢复的内容落到当前仓库
- 明确官方底层、LIO-SAM 痕迹、自研节点的边界

要做的事：

1. 运行 `scripts/recover_go2_backup.ps1`
2. 梳理真实存在的 topic、service、action 名称
3. 整理旧日志中的关键节点关系图

完成标志：

- 能列出“底层输入/输出接口清单”
- 能列出“缺失源码清单”

## Phase 1：协议先行

目标：

- 固化上层不依赖底层实现的中间协议

优先定义：

1. `WorldState`
2. `NavigationSubgoal`
3. `NavigationFeedback`
4. `SafetyDecision`

完成标志：

- 上层任务层与安全层不再直接依赖具体 SLAM 实现

## Phase 2：适配层，而不是改底层

目标：

- 把官方 SLAM / Navigation 或现有 ROS2 链路包到同一接口后面

建议做法：

1. 写一个 `SlamNavigationAdapter`
2. 只暴露上层关心的能力：
   - 当前位姿
   - 地图引用
   - 目标下发
   - 导航状态
   - 取消 / 重规划
3. 先对接日志回放或假数据，再对接真机 topic

完成标志：

- 上层代码无需知道底层是官方导航还是 `lio_sam_ros2`

## Phase 3：结构化语义层

目标：

- 把相机、激光、位姿、地图状态融合成统一世界状态

最小版本先做：

1. 机器人位姿
2. 可通行区域 / 阻塞区域
3. 关键目标列表
4. 风险事件列表
5. 当前任务阶段

不要一开始就做很重的 3D 语义地图，先保证：

- 有统一表示
- 能驱动安全监督
- 能供任务层消费

## Phase 4：安全监督层

目标：

- 让任何高层任务都必须经过安全审批

第一版规则建议只有 5 类：

1. 放行
2. 限速
3. 暂停
4. 急停
5. 请求重规划

优先判断的输入：

- 路径前方风险
- 目标附近风险
- 导航错误状态
- 网络质量异常

## Phase 5：任务层与弱网交互

目标：

- 让远端不再直接发“连续控制量”，而是发任务和约束

第一版建议：

1. 人发任务
2. 系统转成阶段目标
3. 阶段目标转成导航子目标
4. 只回传摘要、事件和关键帧

这样弱网下更稳，因为：

- 下行是目标级控制，不是遥操作
- 上行是摘要级回传，不是全量视频

## 现在最值得立刻做的具体任务

如果只选一件事，我建议先做：

1. 把真实 GO2W / ROS2 输入输出接到 `SlamNavigationAdapter`

如果可以并行做两件事，再加上：

2. 把 YOLO / 风险信息填进 `WorldState`

如果要第三件事：

3. 用 `SafetySupervisor` 接管所有导航目标的最终放行

## 不建议现在就做的事

下面几件事先别作为主线：

- 深改官方 SLAM 内部算法
- 一开始就重写完整导航栈
- 让 LLM 直接输出速度控制量
- 一开始就追求完整 3D 语义地图

这些都容易把项目复杂度拉爆，而且会让你迟迟进不了“可跑通闭环”的状态。
