总判断

闭环成立

当前主链路符合规划：中文任务和 UI 输入进入 C++ operator core，目标必须来自 registry，SafetyGate/QueueExecutor 在发车前和运行中做拦截，底层通过 SLAM Gateway 调 Unitree SLAM/Navigation。

安全仍有缺口

LiDAR summary 已能进入 gateway safety，但 raw XT16 PointCloud2 到 summary 的实时几何检测仍需补齐；IMU/odom health 仍是 phase-1 默认值。Python 执行路径的运行中 pause/watchdog 弱于 C++，应避免作为主要真实执行入口。

下一阶段重点

不要先替换 SLAM 主闭环。继续补 raw XT16 点云几何检测、结构化任务链路展示、真实 health topic，再把 odom/IMU 相对运动保持在 dry-run/stub 分支内推进。

已落地修正：chen_jiayu_station 的描述要求站立验证，但缺少机器可读 tag。本次已为该 topology node 添加 needs_standing_verification；另外 capture_keyframe 已统一为可配置真实命令，relative_motion 已改为 relative_motion_preview dry-run only，不会生成真实运动命令。

当前闭环流程

Operator UI/Web 显示状态、输入中文任务、切换 dry-run/execute、弱网模式、SLAM 管理。
C++ Operator Panel 主入口。优先确定性语义路由，必要时 HTTP LLM 或 Python fallback。
Map Registry 唯一可执行目标来源。PCD、拓扑点、重定位 anchor、tags 统一在这里。
SafetyGate 检查 SLAM health、localization、current pose、target、battery、fresh trusted obstacle。
QueueExecutor 顺序执行 navigate/report/capture 事件，运行中轮询 world_state，异常 best-effort pause。
SLAM Gateway 封装 Unitree relocate/navigate/pause/resume/get_world_state，gateway 侧再做 safety。
Unitree SLAM 负责实际几何定位、重定位、路径导航、导航反馈。
对用户之前的定位疑问：当前逻辑不是“周围都安全才允许重定位和真实执行”。重定位依赖 SLAM/anchor/pose；真实导航只把新鲜、可信的障碍摘要作为阻断条件。没有 D435/点云摘要时不应被误解为“全环境必须安全”，但在 XT16 近场安全接好前，真实执行仍需要额外保守。

点云柱体检测方案

建议做，但先做轻量几何

第一版不要上 PointPillars/CenterPoint 这类训练模型。更合适的是裁剪前方/侧方 ROI、地面去除、欧式聚类、估算高度/半径/长宽比，多帧稳定后输出 person_like、pole_like、static_obstacle。

接入点

应接到 robot/slam_gateway_refactor/src/lidar_geometry_perception.cpp，输出 LocalObstacleSummary，source 为 lidar_pointcloud。不要走 generic edge_perception_summary.json 做安全，因为 generic loader 明确 safety_wired=false。

LLM 策略与 LoRA 判断

安全不是 prompt-only

真实运动仍由 registry、SemanticRouter、TaskQueue、SafetyGate、QueueExecutor 和 SLAM Gateway 约束。LLM 即使输出错误，也不能绕过已注册目标和执行前安全门。

智能层偏窄

当前 C++ HTTP LLM schema 主要是 reply + targets[] + capture_keyframe，会让系统看起来像“从候选拓扑点里检索”。拓扑点越多，这种感觉越明显。

LoRA 暂不主线

LoRA 可以后续学习格式和策略偏好，但当前优先级低于 schema 约束、validator、capability contract、评估样本和 UI 可解释性。

本轮已推进：新增 capability_contract，把 mapped_topology_navigation、capture_keyframe、relative_motion、mapless_scout、raw_base_control 的 ready/conditional/not_wired 状态显式交给 Python planner 和 C++ HTTP LLM；C++ panel 也增加未接线能力硬拦截，遇到相对运动、mapless scout 或 raw base control 请求时直接不下发命令。
层级 应该负责 不应该负责 当前建议
Prompt 短硬约束、输出 schema、工具白名单、能力边界。 不承载安全裁决，不背地图坐标，不靠长篇规则穷举所有场景。 保留，但从“禁止列表”升级为 capability_contract。
规则/Validator 目标必须注册、任务队列合法、未校准点阻断、上下文策略覆盖。 不做自然语言语义泛化。 继续作为第一责任层，补 safety golden vectors。
Registry/RAG 运行时注入 node_id、中文名、aliases、tags、photo_required、needs_calibration。 不训练进模型长期记忆。 继续唯一事实源，避免地图知识固化到 LoRA。
LLM 意图归纳、歧义澄清、任务级排序、解释阻断原因。 不输出坐标、速度、cmd_vel、raw Unitree API，不参与实时控制。 增强 intent schema，例如 mode/confidence/reason/unsupported_capability/clarification/targets。
LoRA 学习稳定 JSON、策略偏好、中文指令归一化、弱网/低电/未知目标响应。 不学习安全阈值、地图坐标、传感器底层控制。 等 schema+validator+hybrid 在评估集上仍不达标，再做 A/B/C 对比。

TI 雷达分支规划

边界

AWR2243 等 TI mmWave 方案适合作为外接 NX 侧处理链。raw ADC、雷达点云、track、生命体征估计留在 NX；GO2W 主机只接收 bounded summary。生命体征结果在 UI 中表述为“疑似微动/呼吸样候选”。

不做的事

不把雷达 raw data 发给 LLM，不把雷达候选当医学结论，不让 TI 雷达解除 XT16/D435/SLAM 阻断，不在外参/时间同步/故障注入前接入 SafetyGate 授权运动。

UI/LLM 显示候选、range、azimuth、confidence、age。 作为巡检证据和任务报告，不作为底盘命令。 只增加谨慎。
