# 多传感器感知扩展方案

## 总原则

传感器不要一开始全堆进 SLAM 主闭环。推荐分层：

```text
LiDAR：先服务定位、障碍摘要、几何目标
RGB-D：补视觉语义、门状态、关键帧
毫米波雷达：补恶劣环境下的动态目标和速度
外接 NX：运行额外感知，不抢主控资源
```

## 点云频率是否支持

必须真机测：

```bash
ros2 topic hz /utlidar/cloud
ros2 topic hz /utlidar/robot_pose
ros2 topic hz /uslam/localization/odom
ros2 topic hz /uslam/navigation/global_path
ros2 topic bw /utlidar/cloud
```

初步判断：

| 点云频率 | 可支持能力 |
|---:|---|
| `< 3 Hz` | 展示、低频摘要 |
| `5 Hz` | 低速障碍检测、保守巡检 |
| `10 Hz` | 动态目标跟踪、局部安全判断 |
| `15-20 Hz` | 更实时的几何检测 |
| `> 20 Hz` | 重点看计算和带宽压力 |

如果机器狗速度控制在 `0.3-0.5 m/s`，`5-10 Hz` 的点云通常足够做保守安全摘要。

## LiDAR 几何柱状目标检测

建议做，但第一版不做重模型。

流程：

```text
点云裁剪
地面去除
聚类
估计高度 / 宽度 / 半径
多帧跟踪
输出 person_like / pole_like / static_obstacle
```

价值：

1. 疑似行人检测。
2. 柱子、门框、障碍物识别。
3. 给安全层提供更明确风险。
4. 给语义地图提供几何锚点。

不建议第一版直接上 `PointPillars / CenterPoint`，因为需要数据集、标注、训练和部署优化。

## 深度相机接入

推荐优先级高于毫米波雷达。

定位：

```text
深度相机先作为 Vision Perception 模块。
不先接入 SLAM 主闭环。
```

可提供：

1. 人、箱子、桌椅等视觉类别。
2. 门是否打开。
3. 近距离障碍确认。
4. 关键帧回传。
5. 给 LLM 的语义摘要。

接入流程：

```text
RGB-D Camera
        ↓
ROS2 camera node
        ↓
RGB 检测模型
        ↓
Depth 关联 3D 位置
        ↓
SemanticObject
        ↓
WorldStateBuilder
```

工程要求：

1. 标定 `camera_link -> base_link` 外参。
2. 分辨率先用 `640x480`。
3. 帧率先限制在 `10-15 FPS`。
4. RGB 和 Depth 对齐。
5. 只输出检测结果和关键帧，不把全量视频喂给 LLM。

## AWR2243 毫米波雷达 + 外接低配 NX

建议作为第二阶段创新增强，不作为第一阶段主线。

优势：

1. 黑暗、烟雾、弱光下仍可工作。
2. 能直接测速度，多普勒信息对动态目标很有价值。
3. 可作为 LiDAR 和视觉的冗余安全传感器。
4. 比赛创新表达更强。

风险：

1. AWR2243 更像雷达前端，不是即插即用高级感知模块。
2. 需要原始 ADC、点云或 track 处理链。
3. 室内容易有多径和鬼影。
4. 标定、同步、ROS 接入工作量较大。
5. 角分辨率通常不如 LiDAR。

推荐架构：

```text
主机器狗 NX
unitree_slam / SLAM Gateway / SafetySupervisor / LLM summary

外接低配 NX
mmWave 处理 / RGB-D 检测 / 目标跟踪

两者之间
只传 radar_tracks / semantic_objects / risk_events
```

不要传：

```text
原始 ADC
大流量点云
连续高清视频
```

## 传感器优先级

```text
P0：SLAM Gateway + LiDAR 局部障碍摘要
P1：LiDAR 几何柱状目标检测
P2：RGB-D 视觉语义
P3：毫米波雷达 + 外接 NX
```

最终表达：

> 以 LiDAR-SLAM 为定位基础，以 RGB-D 提供近场语义，以毫米波雷达提供恶劣环境下的动态目标冗余感知，最终统一压缩为 WorldState 给本地 LLM 做任务级规划。
