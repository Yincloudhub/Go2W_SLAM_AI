# 当前闭环状态与近期优化清单

## 当前结论

GO2W 项目已经从“脚本拼命令”进入“可解释闭环入口”阶段。

当前链路：

```text
用户中文指令
  -> go2w_agent_entry.py
  -> 目标解析 / hybrid 或真实 LLM
  -> registry 点位校验
  -> 近距/低电量/弱网/未知目标安全兜底
  -> 生成 SLAM Gateway JSON
  -> 网关 preflight
  -> 可选 execute
  -> 到点监控与 pause
  -> JSON / CSV 日志
```

当前最重要的工程原则：

```text
LLM 可以建议任务，但不能绕过安全层。
registry 是唯一可执行目标来源。
PCD 点击点必须经过现场校准才能变成 verified 点。
```

## 已具备能力

| 能力 | 当前状态 | 说明 |
|---|---|---|
| 中文目标解析 | 可用 | 中文 `name/aliases` 可匹配到英文 `node_id` |
| PCD 点位导入 | 可用 | 通过 UTF-8 文件或 base64，避免 PowerShell 中文污染 |
| 地图 registry | 可用 | 当前使用 `/home/unitree/test.pcd` |
| SLAM 状态读取 | 可用 | 可读 current pose、localization、slam health、safety |
| hybrid 快速规划 | 可用 | 已知目标不必等待真实 LLM |
| 真实 LLM dry-run | 可用 | 但耗时约 13-16 秒 |
| 近距目标 hold | 已加固 | 即使真实 LLM 输出导航，也会强制 safe_hold |
| 低速/地形模式入口 | 已加固 | 默认 `nav_speed_mps=0.3`、`nav_mode=1` |
| 执行日志 | 可用 | 写入 `artifacts/robot_runs` 的 JSON/CSV |
| 复合命令串行队列 | 已接入 | 多目标命令可展开为 `navigate -> wait -> capture -> navigate -> report` |
| 中文 base64 入口 | 已加固 | 新增 `scripts/go2w_encode_command.py`，现场避免 PowerShell/SSH 编码污染 |

## 2026-05-25 更新：串行任务闭环

本轮已经把“去701门外走廊拍照，然后回尹思园工位”从单目标规划升级为串行任务队列。

当前链路：

```text
中文输入
  -> go2w_agent_entry.py
  -> UTF-8/base64 可选安全入口
  -> local_llm_planner 解析 matched_targets
  -> task_queue 顺序展开
  -> run_robot_closed_loop 逐段执行
  -> 每段导航前 gateway preflight
  -> 到点 pause / capture_keyframe 事件 / 中文 user_reply
  -> semantic_trace + queue_execution 日志
```

今晚实测优先级：

1. 先 `--dry-run --brief`，确认 `task_queue_targets=room_701_corridor|yin_siyuan_station`。
2. 再低速 `--execute --brief --arrival-monitor-s 35`，人在旁边遥控器兜底。
3. 如果 701 点误差大，停止扩展任务，先用 live pose 校准 `room_701_corridor`。
4. 如果返回尹思园工位误差可接受，再做第二条命令验证反向顺序。

## 近期优化优先级

### P0：现场点位校准闭环

目标：

把 PCD 点击点转成可实际复用的现场点位。

动作：

1. 对每个 `needs_calibration` 点做 dry-run。
2. 选择安全点位做低速真实导航。
3. 到点后人工确认停靠位置和朝向。
4. 用 live pose 覆盖 registry 点位。
5. 删除该点 `needs_calibration`。

验收标准：

```text
至少 3 个点位完成校准：
yin_siyuan_station
zhao_bo_office_front
yang_shuyang_station 或 room_701_corridor
```

### P0：真实执行前安全摘要

目标：

每次真实执行前，用一屏摘要告诉现场人员“将要去哪、速度多少、模式多少、是否在目标附近、是否需要拍照”。

建议输出字段：

```text
command
resolved_target
target_name
distance_to_target_m
plan_mode
slam_command.target_pose.x/y/yaw
nav_speed_mps
nav_mode
photo_required
preflight_allowed
preflight_reason
needs_calibration
```

验收标准：

执行前无需打开完整 JSON，也能判断是否允许下发。

### P1：点位姿态校准

问题：

当前多数 PCD 点击点只有 `x/y`，方向默认 `yaw=0`。这会导致到点后姿态不符合“面向工位/门口/走廊”的需求。

动作：

1. 在现场到点后读取 live yaw。
2. 对门口类点位，人工指定面向门/走廊方向。
3. registry 中写入 `yaw` 或四元数。
4. 到点判断可先只看距离，姿态作为观察指标，不立即卡死。

验收标准：

赵博办公室门口、701门外走廊两个拍照点具备明确朝向。

### P1：日志复盘格式

目标：

让每次现场实验都能复盘。

建议每次真实执行自动记录：

```text
run_id
git_commit
command
resolved_target
planner_route
force_llm
llm_elapsed_s
plan_mode
slam_command
preflight
execute_result
arrival_samples
final_distance_m
operator_note
```

验收标准：

一次失败导航能定位到是点位错、定位错、LLM 错、网关错还是执行错。

### P1：拍照/语音工具落地

当前：

`photo_required` 点位能在计划里生成 `capture_keyframe`，但实际拍照链路还没有稳定封装。

动作：

1. 封装 `capture_keyframe` 为真实工具。
2. 记录图片路径和时间戳。
3. 语音工具保留小音量默认值。
4. 语音不要和导航抢实时链路，建议到点后执行。

验收标准：

“去赵博办公室门口拍照”能生成并保存一张带 run_id 的关键帧。

### P2：真实 LLM 耗时优化

现状：

真实 LLM light 模式耗时约 13-16 秒；hybrid 路径已知目标可 0 秒级生成计划。

策略：

```text
已知目标、简单导航：hybrid deterministic
未知目标、复杂语义：真实 LLM
危险/低电/定位失败：规则层直接拒绝或确认
```

不建议让真实 LLM 成为每一次简单导航的必经路径。

验收标准：

常用点位导航从用户输入到生成命令小于 2 秒。

## 下一个现场推荐流程

```text
1. 机器狗站立，现场人员握遥控器。
2. 运行 status brief，只读确认定位与 safety。
3. 对目标点执行 dry-run full-output。
4. 人工看摘要，确认目标、速度、mode、距离。
5. 真实执行一个短距离目标。
6. 到点后 pause。
7. 记录 final_distance_m 和现场肉眼偏差。
8. 如点位偏差明显，遥控器微调后 calibrate-node。
9. commit registry。
```

## 暂不推进的事项

以下事项暂缓，避免扩散：

```text
不重写 unitree_slam。
不直接把 LLM 放进实时控制环。
不在点位未校准前做长距离自主巡航。
不把 RGB-D、毫米波雷达接入主闭环，先保留为第二阶段增强。
```
