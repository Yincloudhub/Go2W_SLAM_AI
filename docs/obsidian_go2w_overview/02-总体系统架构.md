# 总体系统架构

## 分层架构

```text
远端用户 / 比赛演示端
        ↓
弱带宽交互层
        ↓
本地 LLM Planner
        ↓
TaskManager / Executor
        ↓
SafetySupervisor
        ↓
SLAM Gateway
        ↓
Unitree SLAM / Navigation
        ↓
GO2W 本体执行
```

语义闭环的汇报口径见 [[10-语义闭环汇报口径]]。核心边界是：`SLAM` 负责几何定位和导航反馈，`Map Registry` 负责语义绑定，`WorldStateBuilder` 负责摘要压缩，`LLM Planner` 只做低频任务级决策。

状态上行链路：

```text
LiDAR / IMU / Odom / Camera / mmWave
        ↓
SLAM Gateway + Perception Adapters
        ↓
WorldStateBuilder
        ↓
SafetySupervisor / LLM / Remote UI / Logger
```

## 关键模块职责

| 模块 | 职责 | 不负责 |
|---|---|---|
| `SLAM Gateway` | 封装官方 SLAM 位姿、导航状态、暂停恢复、重定位 | 不做自然语言理解 |
| `MapManager` | 管理 PCD、map_id、拓扑点、重定位锚点 | 不直接控制机器狗 |
| `LocalizationManager` | 判断 `map_loaded`、`relocating`、`localized`、`lost` | 不识别语义物体 |
| `LiDAR Perception` | 点云障碍摘要、动态目标、柱状几何检测 | 不识别颜色文字 |
| `Vision Perception` | RGB-D 语义目标、门状态、关键帧 | 不直接改 SLAM |
| `Radar Perception` | 毫米波动态目标、速度、恶劣环境冗余 | 不作为第一阶段主链 |
| `WorldStateBuilder` | 融合状态并压缩给 LLM / 远端 | 不做最终安全裁决 |
| `SafetySupervisor` | 暂停、急停、限速、重规划 | 不依赖 LLM 才能停车 |
| `LLM Planner` | 任务理解、子目标选择、通信策略 | 不直接调用 `slam_operate` |

## 运行时数据流

```text
1. SLAM Gateway 读取 rt/slam_info 和 rt/slam_key_info。
2. LiDAR Perception 读取 /utlidar/cloud 或 range_info。
3. Vision Perception 读取 RGB-D 检测结果。
4. Radar Perception 读取毫米波 tracks。
5. WorldStateBuilder 融合成结构化状态。
6. SafetySupervisor 高频检查是否允许继续运动。
7. Event / Summary Gate 决定是否触发 LLM。
8. LLM 输出任务级工具调用。
9. PlannerPolicyValidator 和 SafetySupervisor 二次审核。
10. Executor 调用 SLAM Gateway 执行。
```

## 实时性分配

| 层级 | 频率 | 是否经过 LLM |
|---|---:|---|
| 点云、odom、IMU、局部避障 | 10-50 Hz | 否 |
| SLAM Gateway 状态 | 2-10 Hz | 否，先摘要 |
| SafetySupervisor | 5-20 Hz | 否 |
| WorldState summary | 0.2-1 Hz 或事件触发 | 是 |
| 远端状态显示 | 事件触发或低频 | 否 |

核心原则：

```text
实时安全闭环不经过 LLM。
LLM 只做任务级低频规划。
```
