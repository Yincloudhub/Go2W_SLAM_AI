# 比赛表达与风险控制

## 2026-05-24 收敛判断

当前研电赛主线应从“完整边缘自治系统”收敛为“稳定可展示的本地语义 SLAM 闭环”。

优先展示：

```text
中文指令
-> 语义拓扑点匹配
-> SLAM / localization / safety 状态检查
-> 本地 hybrid 或 LLM 规划
-> 安全策略兜底
-> 低速地形模式导航
-> 到点暂停
-> 拍照或关键帧
-> 结构化日志
```

对应详细执行方案见：

- [[09-研电赛下一步执行方案]]
- [[10-语义闭环汇报口径]]

## 推荐比赛表达

项目可以表达为：

> 面向弱带宽远程交互场景，构建四足机器人本地语义感知与边缘自治系统。系统基于 GO2W 官方 SLAM 实现几何定位与导航，通过 SLAM Gateway 统一封装定位、地图和任务反馈，融合 LiDAR、RGB-D 与毫米波雷达的结构化感知结果，并由本地轻量 LLM 在低频 WorldState 摘要上完成任务级规划，最终由安全监督层闭环执行。

## 创新点组合

### 1. 黑盒 SLAM 的结构化封装

把官方 SLAM 的 topic、service、状态反馈封装为：

```text
CurrentPose
LocalizationState
SlamHealth
NavigationTaskState
MapState
```

### 2. 多空间地图与重定位锚点

强调：

```text
PCD 几何地图 + 拓扑点 + 重定位锚点 + 地图切换状态机
```

### 3. 多传感器摘要感知

不是把所有原始数据都传给远端，而是统一成：

```text
SemanticObject
LocalObstacleSummary
RadarTrack
RiskEvent
```

### 4. 本地小模型闭环规划

强调：

```text
大模型离线蒸馏
小模型本地运行
工具调用约束
安全层二次审核
```

### 5. 弱带宽交互

展示：

```text
低频状态摘要
关键帧事件上传
风险事件回传
人工确认节点
```

## 推荐演示场景

场景一：701 室内到门口。

```text
用户下发：去 701 门口观察。
系统确认定位正常。
LLM 输出 target_node=701_door_inside。
安全层放行。
到达后回传状态和关键帧。
```

场景二：定位未验证时拒绝移动。

```text
用户下发：去走廊巡视。
系统发现 map_loaded 但 not localized。
LLM 输出 request_relocation / hold_position。
系统请求人工确认或重定位。
```

场景三：弱网和障碍物。

```text
前方有人进入路径。
LiDAR 或 RGB-D 输出 RiskEvent。
SafetySupervisor 暂停。
远端只收到摘要和关键帧。
```

场景四：多传感器增强。

```text
视觉受限时，毫米波雷达检测移动目标。
系统输出 moving_target risk。
机器狗保守停车。
```

## 风险控制

| 风险 | 控制策略 |
|---|---|
| SLAM 不稳定 | 先做 `SlamHealth` 和 `LocalizationState` |
| PCD 任意点无法定位 | 使用重定位锚点和人工初始位姿 |
| LLM 输出错误 | JSON schema + PolicyValidator + SafetySupervisor |
| 点云频率不够 | 降速，先做低频障碍摘要 |
| RGB-D 受光照影响 | 只做语义增强，不做唯一安全来源 |
| 毫米波多径鬼影 | 只作为冗余动态目标来源 |
| NX 算力不够 | 外接感知 NX，只传结构化结果 |

## 不建议展示为

```text
LLM 全自主控制机器狗
任意位置 PCD 自动定位
LiDAR 完成全部语义识别
毫米波雷达替代 SLAM
深度相机直接解决所有导航问题
```

## 推荐展示为

```text
底层 SLAM 稳定定位
外层语义状态统一建模
多传感器结构化摘要
本地 LLM 任务级规划
安全层实时闭环兜底
弱网下只传关键状态和事件
```
