# 研电赛下一步执行方案

> 这是 2026-05 的比赛方案快照，不再作为当前“下一步”清单。当前唯一软件任务
> 和禁止重复事项见 [[22-上下文归档与新Session交接]]。

## 核心判断

研电赛下一步不要继续横向扩功能，而是先把一个可稳定展示的闭环打磨出来。

当前项目最有比赛价值的表达不是“LLM 控制机器狗”，而是：

```text
弱带宽远程交互场景下，四足机器人在本地完成 SLAM 状态理解、语义目标解析、安全策略判断和任务级规划，并由独立安全层兜底执行。
```

评委真正会看三件事：

1. 能不能跑起来。
2. 创新点是不是清楚。
3. 失败时是不是可控。

所以后续所有工作都应该围绕“稳定演示 + 可解释创新 + 风险可控”推进。

## 比赛 MVP 场景

### 主场景：中文指令到办公室门口巡检

推荐主线：

```text
用户输入：去赵博办公室门口看一下，到了拍一张照。
系统解析：赵博办公室门口 -> zhao_bo_office_front。
系统检查：SLAM ok、localized、safety allow、目标存在。
规划输出：mapped_navigation + wait_until + capture_keyframe。
执行策略：低速、地形模式、到点 pause。
回传结果：到达状态、最终距离、关键帧路径、结构化日志。
```

这个场景最适合比赛，因为它同时覆盖：

- 中文自然语言交互。
- 语义拓扑点匹配。
- 本地 LLM / hybrid 规划。
- SLAM Gateway 执行。
- 到点反馈。
- 拍照任务。
- 结构化日志。

### 安全兜底场景：已在目标附近不重复导航

推荐展示：

```text
机器狗已经在尹思园工位附近。
用户输入：去尹思园工位。
系统输出：safe_hold。
理由：distance_to_requested_target_m <= arrival_distance_m。
```

这个场景可以证明：

```text
LLM 不是直接控制底盘，安全策略能覆盖 LLM 错误输出。
```

### 异常场景：未知目标拒绝执行

推荐展示：

```text
用户输入：去不存在的办公室。
系统输出：human_confirm。
不生成 create_navigation_subgoal。
```

这个场景可以证明：

```text
目标必须来自 registry，不能让模型凭空编点。
```

### 弱网场景：只发摘要和关键帧

推荐展示可以先用模拟 world_state：

```text
bandwidth_kbps < 200
系统先 set_communication_policy
drop raw_video / dense_pointcloud / high_rate_images
send task_state / navigation_feedback / world_state_summary
```

这个场景贴合“边缘自治”和“弱带宽远程交互”的比赛表达。

## 下一步工程优先级

### 第 1 优先级：点位校准

目标：

把可展示路线中的点位校准到真实可停靠位置。

优先校准：

1. `yin_siyuan_station`：近距 hold 与校准参考点。
2. `zhao_bo_office_front`：主展示点，办公室门口拍照。
3. `room_701_corridor`：走廊拍照点，可展示门口/走廊巡检。
4. `yang_shuyang_station`：工位类目标，作为备用演示点。

完成标准：

```text
每个展示点完成：
dry-run 通过
真实低速导航一次
到点后人工确认
calibrate-node 写回 live pose
删除 needs_calibration
记录 final_distance_m
```

### 第 2 优先级：执行前摘要

目标：

让现场人员不用看长 JSON，也能判断能不能执行。

必须显示：

```text
中文指令
匹配 node_id
中文目标名
当前距离
是否已经在目标附近
是否 needs_calibration
是否 photo_required
速度
mode
preflight_allowed
preflight_reason
将要下发的 action
```

完成标准：

```text
执行前摘要一屏可读。
现场人员能在 5 秒内判断是否按 execute。
```

### 第 3 优先级：拍照工具

目标：

把 `capture_keyframe` 从计划字段变成真实可执行工具。

最小实现：

```text
到点后调用相机截图或关键帧保存。
文件名包含 run_id、target_node、timestamp。
日志里写 image_path。
```

完成标准：

```text
去赵博办公室门口拍照
=> 到点
=> pause
=> 保存一张图片
=> 日志记录图片路径
```

### 第 4 优先级：比赛演示日志

目标：

每次演示都能复盘，也能作为答辩材料。

日志必须包含：

```text
git_commit
command
resolved_target
planner_route
force_llm
llm_elapsed_s
plan_mode
preflight_allowed
slam_command
execution_result
arrival_samples
final_distance_m
image_path
operator_note
```

完成标准：

```text
一次演示结束后，可以直接拿日志解释系统做了什么、为什么这么做、有没有到达。
```

## 比赛创新点收敛

### 主创新点 1：黑盒 SLAM 的结构化 Gateway

表达：

```text
官方 SLAM 负责定位与导航，本项目把黑盒状态封装成可被上层决策使用的结构化 WorldState。
```

对应证据：

- `current_pose`
- `localization`
- `slam_health`
- `navigation`
- `safety`

### 主创新点 2：语义拓扑点 + 本地规划

表达：

```text
自然语言目标不是直接转坐标，而是先映射到 registry 中的语义拓扑点，再生成受约束工具调用。
```

对应证据：

- 中文 `name/aliases`
- 英文稳定 `node_id`
- `create_navigation_subgoal`
- `target_node` 必须存在于 registry

### 主创新点 3：LLM 输出安全兜底

表达：

```text
LLM 只负责任务级规划，执行前由规则层校验。近距、低电、弱网、未知目标等场景会覆盖模型输出。
```

对应证据：

- 近距目标强制 `safe_hold`
- 未知目标强制 `human_confirm`
- 低电任务禁止直接导航
- 弱网通信策略模板化

### 备选创新点：弱带宽摘要交互

表达：

```text
机器人本地完成高频感知和规划，只向远端传状态摘要、风险事件和关键帧。
```

对应证据：

- `semantic_only`
- drop raw video / dense pointcloud
- send task state / navigation feedback / world state summary

## 暂时不要投入的方向

为了研电赛进度，以下方向先不要成为主线：

```text
不要优先微调模型。
不要优先接毫米波雷达进主闭环。
不要优先接 RGB-D 进导航闭环。
不要追求任意点自主导航。
不要做长距离无人看护巡航。
不要把真实 LLM 放到每一次简单导航必经路径。
```

这些都可以作为后续增强或答辩展望，但不应该阻塞当前 MVP。

## 两周内推荐节奏

### 第 1-2 天

```text
校准尹思园、赵博、701门外走廊。
实现执行前摘要。
确认地形模式低速执行稳定。
```

### 第 3-5 天

```text
封装拍照工具。
完成一次完整主场景演示。
补充日志字段。
```

### 第 6-8 天

```text
准备 3 个失败兜底演示：
已在目标附近
未知目标
弱网策略
```

### 第 9-12 天

```text
录制演示视频。
整理系统框图。
整理创新点证据链。
准备答辩话术。
```

## 下一次现场执行建议

下一次不要一上来跑很多点。建议只做一条主线：

```text
1. status brief
2. 赵博办公室门口 dry-run full-output
3. 人工确认摘要
4. execute 低速导航
5. 到点 pause
6. 保存关键帧或先记录缺失
7. final_distance_m + 人工偏差备注
8. calibrate-node 写回
9. commit
```

如果这条主线稳定，研电赛的核心作品就基本成立。
