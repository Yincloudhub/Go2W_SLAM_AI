## 0. 先看这一页

今晚优先做：

1. 上电后只启动 XT16、SLAM、D435 轻量深度侧车和 Web UI。
2. 机器人趴下时完成状态检查、重定位和近场障碍阻断测试。
3. 电量充足、定位正常、安全门正常后，再站立并用遥控器人工移动到现场点位录点。
4. 每个新点都执行“登记当前位置”和“现场验证”。
5. 真实自主导航必须最后做，先单点、短距离、空旷路线，再逐步增加距离。

不要做：

- 不要在低电量、关节发热、定位异常或 D435 摘要过期时开真实执行。
- 不要把“切回仅预演”当作急停。紧急情况优先使用现场已验证的物理遥控接管或停机手段。
- 不要在沿用现有地图录点时点击“开始建图”。
- 不要盲目重定位。机器人必须物理摆在所选锚点附近，姿态也应接近锚点记录姿态。
- 不要直接跑多点任务。先验证最近邻单点路线，再验证往返，再验证多点。

重要状态：

- 机器人在 2026-06-02 关机前电量已经降到 `20%`。重新上电后先充电和复查。
- 建议电量达到 `35%` 以上再开始站立录点或运动测试。
- 电量 `<=20%` 时停止真实运动测试。
- `DeepYOLO` 是可选语义侧车，离线不阻塞主链路。
- D435 轻量深度摘要是当前真实运动硬门槛，离线或过期时禁止真实执行。
- TI 雷达 / NX 是后续可选增强项，当前未接入显示“未接入，可选增强”属于正常状态。

## 1. 系统在哪里运行

运行关系：

```text
机器人本机
  XT16 driver
  Unitree SLAM
  C++ GatewayClient / SafetyGate / QueueExecutor / SemanticRouter
  Python Web UI 薄服务
  D435 轻量深度摘要侧车

现场电脑
  SSH 隧道
  浏览器 http://127.0.0.1:8765/
```

Web UI 和核心执行链路运行在机器人侧。现场电脑只负责 SSH 隧道和浏览器，所以电脑可以更换，机器人管理 IP 也可以变化。

更换现场电脑或管理 IP 时，只需要修改 SSH 连接地址。不要因为现场电脑换网而修改机器人内部的 `GO2W_NETWORK_INTERFACE=eth0`，也不要随意修改 `/unitree/module/unitree_slam/config`。

## 2. 上电前人工检查

至少两个人在场：一人操作电脑，一人拿遥控器并观察机器人。

检查：

- 机器人周围箱子、桌脚、线缆和人员已经清开。
- 初始位置右侧曾经发生顶箱事故，右侧必须重点检查。
- D435 双目深度相机 USB、供电和固定位置正常。
- XT16 雷达供电和线缆正常。
- 机器人关节没有异常发热、卡滞、异响或外壳损坏。
- 遥控器已经连接，现场人员知道并实际验证过物理接管或停止按键。
- 在没有验证物理接管按键前，不开始真实自主运动。

## 3. 找到机器人 IP

常用地址：

```text
有线直连：192.168.123.18
Wi-Fi：   192.168.3.17
SSH 用户：unitree
SSH 密码：123
```

在 Windows PowerShell 中依次测试：

```powershell
Test-NetConnection 192.168.123.18 -Port 22
Test-NetConnection 192.168.3.17 -Port 22
```

如果地址变化：

1. 查看路由器 DHCP 列表或现场网络管理页面。
2. 在 Windows 中运行 `arp -a` 查看同网段设备。
3. 使用已知的新地址测试 SSH 端口：

```powershell
Test-NetConnection <机器人新IP> -Port 22
```

连接成功后，在机器人 SSH 终端确认机器人自己的地址：

```bash
hostname -I
ip -br addr
ip route
```

现场电脑 IP、机器人 SSH 管理 IP、机器人内部 SLAM DDS 网卡是不同概念。现场电脑或 SSH 地址变化，不等于要修改 SLAM 网卡。

机器人先保持趴下。不要点“允许真实执行”。


```text

```

如果刚重启，`loc=false` 可能是正常的，下一节再做重定位。

在机器人 SSH 终端检查 D435：

```bash
cd /home/unitree/Go2W_SLAM_AI
```

```text
summary_health=ok

roi_left >= 0.15

```

```text
soc
current
bq_ntc
mcu_ntc
```

`soc` 是电量百分比。建议 `>=35` 再开始运动测试，`<=20` 时停止真实运动。

## 7. 重定位

只有机器人确实摆在建图起点或已知锚点附近，且朝向接近记录姿态时，才允许重定位。

通常使用：

```text
mapping_origin
```

UI 中展开“高级控制”，在“重定位锚点 ID”中填写：

```text
mapping_origin
```

点击：

```text
执行重定位
```

确认弹窗。该操作只做 SLAM 重定位，不会移动底盘。

然后等待状态刷新。成功后应看到：

```text
loc=true
map=true
motion=false
safety=ok
```

注意：

- 重定位失败后至少等待 `15` 秒再重试。
- 如果机器人实际不在锚点附近，不要连续重试，也不要随便换锚点碰运气。
- 如果位置明显跳到错误区域，保持仅预演，重新摆回确认过的锚点再试。

## 8. 趴下时必须做一次近场阻断测试

这是 2026-06-01 顶箱事故后的强制恢复步骤。

机器人保持趴下，真实执行保持关闭。

1. 刷新状态，确认 D435 摘要在线。
2. 把箱子分别放到机器人右侧和前方近场区域。
3. 刷新状态，确认 UI 的“运动安全门”锁定或 `/execute on` 被拒绝。
4. 移开箱子。
5. 刷新状态，确认深度摘要恢复正常。

这一节只验证状态，不执行导航。

## 9. 现场录点

### 9.1 沿用现有地图时

录点不需要重新建图。

不要点击：

```text
开始建图
结束并保存
```

现有主地图：

```text
/home/unitree/test.pcd
```

RViz2 不是录点前置条件。普通录点优先只使用 Web UI，减少资源开销。

### 9.2 每个点的录制流程

1. 先确认：

```text
loc=true
map=true
motion=false
safety=ok
```

2. 用遥控器人工移动到目标位置。
3. 停稳，确认朝向合适，刷新 UI 状态。
4. 在“语义拓扑”区域填写：

```text
新拓扑点 ID：只用 ASCII，例如 corridor_corner_01
显示名：例如 走廊拐角
别名：例如 拐角,走廊转角
```

5. 点击：

```text
登记当前位置
```

6. 在拓扑列表中找到该点。机器人仍停在该点附近时，点击：

```text
现场验证
```

后续再次修正同一点坐标时，点击：

```text
更新坐标
```

初始点是受保护点，只能在旧初始点附近、定位正常时点击：

```text
校准初始点
```

### 9.3 点位命名

推荐：

```text
initial_point
chen_jiayu_station
yang_shuyang_station
zhao_bo_office_front
room_701_corridor
corridor_corner_01
```

规则：

- `node_id` 只用英文字母、数字、下划线和短横线。
- 中文放在“显示名”和“别名”里。
- 每个点录完立刻现场验证，不要积压到最后统一处理。
- 误录点使用 UI 的“禁用”，这是软删除，坐标仍会保留，路由会跳过。

### 9.4 录点后保存现场文件

UI 更新拓扑时会在机器人仓库中保存 registry 备份。录点结束后，在机器人 SSH 终端额外保存一份时间戳副本：

```bash
cd /home/unitree/Go2W_SLAM_AI
stamp="$(date +%Y%m%d_%H%M%S)"
cp configs/maps/go2w_real_site_map_registry.json "artifacts/go2w_real_site_map_registry_${stamp}.json"
git status --short
```

不要在机器人上直接提交或丢弃现场 registry 改动。测试结束后由项目负责人统一核对、校验和提交。

## 10. 什么时候才需要建图

只有现场布局变化明显、旧 PCD 无法使用或明确决定重建地图时，才开启建图。

建图是单独的受控任务，不要和普通录点混在一起做。

UI 高级控制中：

```text
开始建图
结束并保存
```

建议保存到新文件，不要直接覆盖旧地图：

```text
/home/unitree/maps/site_YYYYMMDD_HHMM.pcd
```

重建地图后，需要重新核对重定位锚点和所有拓扑点坐标。

## 12. 真实自主导航测试

只有以下条件全部满足才允许开始：

```text
电量建议 >=35%
机器人关节无异常发热
机器人已站立并保持稳定
loc=true
map=true
motion=false
safety=ok
D435 深度摘要 age_ms <= 1000
D435 前、左、右 ROI 置信度均 >=0.15
D435 前、左、右近场距离均 >=0.8m
场地清空
两人在场
遥控器已连接
现场人员已验证物理接管或停止按键
```

测试顺序：

1. 保持“仅预演”，输入最近邻单点任务。
2. 检查 UI 返回的目标是否正确。
3. 只在空旷区域开启“允许真实执行”。
4. 发送最近邻单点任务。
5. 观察起步、转向、避障和到点暂停。
6. 单点成功后，切回“仅预演”。
7. 再验证原路返回。
8. 往返都稳定后，才考虑两个点的串行任务。

不要直接从初始点运行长距离或多点任务。

含拍照的命令目前只会产生 `capture_keyframe` 语义事件，不代表已经保存真实照片文件。真实拍照脚本尚需单独接入。

## 13. 紧急情况

优先级从高到低：

1. 现场人员立即使用已经验证过的物理遥控接管或停止手段。
2. 如果机器人持续顶住障碍、关节发热或姿态异常，确保人员安全后停机。
3. 已经登录机器人 SSH 时，可以发送软件暂停作为第二道手段：

```bash
cd /home/unitree/Go2W_SLAM_AI
PYTHONPATH=src python3 scripts/go2w_agent_entry.py --pause --brief
```

4. UI 中切回“仅预演”，防止继续发送新任务。

注意：

- UI 的“切回仅预演”只阻止后续真实下发，不等价于物理急停。
- SSH 软件暂停依赖网络，不得替代遥控器或现场停机手段。
- 出现一次顶障、定位跳变或异常发热，就停止当晚真实运动，不要连续重试。

建议测试时始终保留第三个 SSH 终端，并提前输入下面命令但不要回车：

```bash
cd /home/unitree/Go2W_SLAM_AI && PYTHONPATH=src python3 scripts/go2w_agent_entry.py --pause --brief
```

需要软件暂停时直接回车。

## 14. 常见问题

### 浏览器打不开

先确认机器人侧 Web UI 终端仍在运行，再确认本地 SSH 隧道终端没有退出。

机器人侧检查：

```bash
pgrep -af 'go2w_operator_web.py'
curl -fsS http://127.0.0.1:8765/api/status?force=1
```

本地检查：

```powershell
Test-NetConnection 127.0.0.1 -Port 8765
```

### MobaXterm 提示找不到 `scriptsgo2w_web_tunnel.py`

原因是 Bash 中使用了 Windows 反斜杠。改成：

```bash
python scripts/go2w_web_tunnel.py
```

### UI 显示 `loc=false`

机器人刚重启时可能尚未重定位。确认机器人确实摆在 `mapping_origin` 附近，再按第 7 节执行重定位。

### UI 显示视觉语义过期

`DeepYOLO` 是可选侧车。它过期不会自动禁止 SLAM，但 D435 轻量深度摘要必须在线。

查看 D435：

```bash
cd /home/unitree/Go2W_SLAM_AI
bash scripts/go2w_stereo_depth_sidecar.sh health
```

### UI 显示外部边缘节点未接入

当前 TI 雷达 / NX 尚未接入，这是正常状态。该节点是可选增强项，不影响现阶段 XT16 + SLAM + D435 主链路。

### UI 显示真实执行无法开启

这是安全门拒绝。先看：

```text
loc
safety
运动安全门
D435 摘要 age_ms
前、左、右距离
前、左、右 ROI 置信度
```

不要通过修改 JSON 或阈值绕过安全门。

### 需要切换机器人 IP

只修改 SSH 连接或隧道参数：

```powershell
python .\scripts\go2w_web_tunnel.py --ssh-host <机器人新IP>
```

不要因为 SSH IP 变化修改 `GO2W_NETWORK_INTERFACE`。

## 15. 测试结束

1. 切回“仅预演”。
2. 确认机器人停止。
3. 保存 registry 时间戳副本。
4. 记录：

```text
测试日期和人员
机器人管理 IP
上电和结束电量
是否成功重定位
录制或更新了哪些 node_id
是否完成近场阻断测试
是否做了真实导航
每条导航路线是否成功
是否发生定位跳变、顶障、异常发热或 USB 掉线
```

5. 不要在机器人上随意清理 `.bak` 文件、现场 registry 修改或运行日志。
6. 正常关机。

## 16. 当前实现边界

- 主链路：XT16 + Unitree SLAM + C++ `SafetyGate` + `QueueExecutor` + Web UI。
- 当前 D435：低频轻量 ROI 深度摘要，真实运动硬门槛。
- 当前 DeepYOLO：可选语义侧车，默认不作为运动授权依据。
- 当前 TI 雷达 / NX：已留接口，尚未接入，默认 `semantic_only`。
- 当前拍照：任务语义事件，尚未完成真实照片落盘。
- 当前 UI：本地浏览器显示，机器人侧 Web 服务通过 SSH 隧道访问。
